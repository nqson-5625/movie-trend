================================================================================
     09. CẨM NANG VẬN HÀNH, BẢO TRÌ VÀ XỬ LÝ SỰ CỐ - MODULE 03: HDFS
================================================================================
Người thực hiện: Giang
Mục tiêu: Xử lý nhanh các sự cố thường gặp của Hadoop HDFS trong quá trình làm đồ án
Nền tảng: Kubernetes (k3s)
================================================================================

--------------------------------------------------------------------------------
1. CÁC LỆNH GIÁM SÁT SỨC KHỎE HDFS HÀNG NGÀY
--------------------------------------------------------------------------------

1. Kiểm tra trạng thái tổng thể của cụm:
   kubectl exec -it -n bigdata pod/hdfs-namenode-0 -- hdfs dfsadmin -report
   (hoặc: make report)

2. Kiểm tra tính toàn vẹn của các blocks trên HDFS (quét lỗi hỏng block):
   kubectl exec -it -n bigdata pod/hdfs-namenode-0 -- hdfs fsck / -files -blocks -locations

3. Xem dung lượng thực tế đang lưu trữ trên HDFS:
   kubectl exec -it -n bigdata pod/hdfs-namenode-0 -- hdfs dfs -df -h /
   kubectl exec -it -n bigdata pod/hdfs-namenode-0 -- hdfs dfs -du -h -s /raw /movies /batch

4. Theo dõi log thời gian thực của NameNode:
   kubectl logs -f pod/hdfs-namenode-0 -n bigdata --tail 100

5. Theo dõi log của DataNode:
   kubectl logs -f pod/hdfs-datanode-0 -n bigdata --tail 100

--------------------------------------------------------------------------------
2. XỬ LÝ CÁC SỰ CỐ ĐIỂN HÌNH (TROUBLESHOOTING)
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
SỰ CỐ 1: NAMENODE BỊ KẸT Ở CHẾ ĐỘ SAFE MODE
- Hiện tượng: Khi chạy lệnh `hdfs dfs -put` hoặc ghi dữ liệu, nhận được thông báo lỗi:
  "Cannot create file... Name node is in safe mode."
- Nguyên nhân: Khi mới khởi động, NameNode cần thời gian chờ các DataNode gửi danh sách 
  block report. Nếu chưa đạt ngưỡng 99% block an toàn, NameNode tự khóa ghi.
- Cách xử lý:
  Bước 1: Kiểm tra trạng thái:
    kubectl exec -it -n bigdata pod/hdfs-namenode-0 -- hdfs dfsadmin -safemode get
  Bước 2: Nếu các DataNode đã kết nối đủ mà NameNode vẫn chưa thoát, cưỡng chế thoát:
    kubectl exec -it -n bigdata pod/hdfs-namenode-0 -- hdfs dfsadmin -safemode leave

--------------------------------------------------------------------------------
SỰ CỐ 2: DATANODE KHÔNG KHỞI ĐỘNG ĐƯỢC DO "CLUSTERID MISMATCH"
- Hiện tượng: DataNode crash. Xem log thấy dòng:
  "java.io.IOException: Incompatible clusterIDs ... namenode clusterID = CID-xxx; datanode clusterID = CID-yyy"
- Nguyên nhân: NameNode bị format lại khiến NameNode sinh ra ClusterID mới, trong khi 
  DataNode vẫn giữ volume cũ.
- Cách xử lý triệt để:
  make clean
  make up
  make init

--------------------------------------------------------------------------------
SỰ CỐ 3: TIẾN TRÌNH JAVA BỊ CRASH DO THIẾU BỘ NHỚ RAM (OOM KILLER / OOMKILLED)
- Hiện tượng: Pod tự động tắt, status K8s ghi `OOMKilled` (Exit code 137).
- Nguyên nhân: Máy ảo 8GB RAM bị quá tải khi chạy đồng thời Kafka, Spark, ES và Hadoop. 
- Cách xử lý:
  1. Kiểm tra cấu hình JVM Heap:
     - NameNode: `-Xms512m -Xmx768m` (Limit K8s: 1024Mi)
     - DataNode: `-Xms256m -Xmx384m` (Limit K8s: 512Mi)
  2. Bật Swap Memory 4 GB trên Ubuntu VM:
     sudo fallocate -l 4G /swapfile
     sudo chmod 600 /swapfile
     sudo mkswap /swapfile
     sudo swapon /swapfile
     echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  3. Kiểm tra RAM tiêu thụ:
     kubectl top pods -n bigdata

--------------------------------------------------------------------------------
SỰ CỐ 4: LỖI KẾT NỐI WEBHDFS TỪ NGOÀI CỤM (HTTP 307 REDIRECT)
- Hiện tượng: Gọi API WebHDFS upload nhận mã 307 chuyển hướng tới DataNode, nhưng báo 
  Connection Refused hoặc Could not resolve host.
- Khắc phục:
  * Sử dụng script `publish_reference.py` (hoặc lệnh `make publish-ref`) đã tích hợp sẵn 
    lệnh `kubectl cp` đẩy file trực tiếp vào Pod NameNode rồi chạy `hdfs dfs -put`, loại bỏ hoàn toàn lỗi chuyển hướng.
  * Hoặc port-forward trực tiếp Web UI / WebHDFS ra host: `make forward`.

--------------------------------------------------------------------------------
SỰ CỐ 5: SAO LƯU VÀ PHỤC HỒI METADATA NAMENODE
- Thao tác sao lưu an toàn:
  1. Ép NameNode lưu trạng thái hiện tại xuống đĩa (Save Namespace):
     kubectl exec -it -n bigdata pod/hdfs-namenode-0 -- hdfs dfsadmin -safemode enter
     kubectl exec -it -n bigdata pod/hdfs-namenode-0 -- hdfs dfsadmin -saveNamespace
     kubectl exec -it -n bigdata pod/hdfs-namenode-0 -- hdfs dfsadmin -safemode leave
  2. Copy thư mục metadata ra ngoài máy chủ để sao lưu:
     kubectl cp -n bigdata hdfs-namenode-0:/opt/hadoop/data/nameNode ./backup_namenode_metadata
